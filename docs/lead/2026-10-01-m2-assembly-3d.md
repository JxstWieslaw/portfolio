## Decisions
- **D1 Stack: `three` + `@react-three/fiber` v9, nothing else.** No drei, no rapier, no postprocessing, no detect-gpu, no worker. The spec (§4.4) lists them for the full M2; in a 40-minute window each is a dependency risk with no visible payoff for a visitor. The generators are pure and memoised, so a worker buys nothing at 3 000 points.
- **D2 Morphing on the CPU, not in a custom shader.** Per-frame lerp of ~3 000 instance matrices is far cheaper than the 2D painter the site already runs at 20 fps (which does 2 600 projections and 5 200 fills per frame). The GPU morph via `three-custom-shader-material` is deferred to M5 polish; the formation data layout (one `Float32Array` per formation) is kept shader-ready.
- **D3 The existing 2D ladder stays as the fallback.** The WebGL layer mounts only on rungs `live` and `reduced-instances`, with WebGL2 available and no `?nogl=1`. Reduced motion, no IntersectionObserver, no canvas, or no WebGL keep today's behaviour byte for byte. No regression is possible on those paths because no new code runs on them.
- **D4 No separate architect pass.** The architecture is in the spec (§4.4, §4.5, §6) and the reconciliation doc; re-deriving it would spend the build window. security-auditor reviews the PR diff because dependencies are added (conventions.md review stage).
- **D5 The three chunk must stay out of the "initial JS (non-3D)" size-limit entry** and get its own ≤ 200 kB gz entry, per spec §6. Named via `webpackChunkName` and verified against the real build output.
- **D6 PR targets `main` and is not merged by the lead.** The card says `auto_main: no`; the API deploy workflow runs on every CI pass on `main`. The hackathon demo runs from the branch (`pnpm dev`) or a Vercel preview, not from production.

## Review stage (reports 3:00–3:04 PM)
### code-reviewer
- **Critical:** `AssemblyLayer` probed WebGL2 on the same canvas `readCapabilities` had already bound to a 2D context, so `getContext('webgl2')` returned null by spec and WebGL would never mount for any visitor. The unit test stub returned a context for every kind on one element and hid it. Fix: separate probe canvas, release the context via `WEBGL_lose_context`, realistic stub plus a positive mount test.
- **High:** the fixed `z-index: 0` layer paints above every non-positioned element; the footer (not positioned, after `<main>`) would be covered by the opaque wash under the contact section. Fix: position the footer.
- **High:** no `.catch` on the dynamic import and no error boundary; a ChunkLoadError or any R3F error would replace the whole home page with Next's error screen. Fix: import `.catch` to a GiveUp component plus a class error boundary that calls giveUp.
- Medium: uncancelled rAF could leave `data-gl="live"` set after unmount (hides the 2D fallback); hero's 2D loop keeps painting under WebGL; pointer repulsion uses a parallel ray under a perspective camera. Low: the give-up flag lived inside one mount.
- Verified OK: 2D path unchanged when WebGL does not mount, wash crossfade, instanced attribute updates, scroll store cleanup, three disposal, no non-null assertions.
- **Decision:** all findings sent back to the authoring agent (fleet-protocol: fix with the authoring persona), Critical and High first, 10-minute cap; the pointer-ray fix only if time remains.

### performance-engineer
- Frame loop measured at 0.215 ms per frame with pointer repulsion (0.122 without) for 3 000 instances on a laptop core; estimated under 3 ms total on a Snapdragon 7-class phone. No per-frame allocations. The reduced rung's 0.45 keep is conservative, not tight.
- Confirmed nothing from three is in the initial chunks; the page chunk carries only the mount gate.
- Lazy set measured: three 189 kB gz, R3F + reconciler 51 kB, its-fine 6 kB, app 4 kB. R3F does `import * as THREE` plus `extend(THREE)`, so tree-shaking cannot apply; the 200 kB spec budget is reachable only without R3F (estimate 125–145 kB with plain three and named imports).
- **High:** the init chain (chunk eval, GL context, 7 target bundles at 7 ms desktop, first shader link) lands as 250–550 ms of long tasks on a phone as early as 300 ms after hydration, while the hydration-bound LCP may still be pending. **High:** the WebGL2 probe ran synchronously inside the hydration effect and was never released. **High:** every resize rebuilt all seven bundles with R3F's default zero debounce (mobile URL-bar collapse mid-scroll).
- Medium: idle breathing rewrites colours and scales every tick; desktop DPR 2 on a full-screen MSAA canvas; 30 fps idle versus the 2D hero's 20; renders and style writes while the layer is invisible. Low: `?? 0` on typed-array reads, rig created in useMemo (StrictMode double-create in dev), the lazy size-limit glob also counts two pages-router chunks (2.7 kB).
- **Decision:** one-liners (resize debounce, DPR 1.5 everywhere, default powerPreference, probe inside the idle callback, 20 fps idle on touch) offered to the builder as optional after the Critical fix. Larger items are follow-ups for the M2 remainder: build only the from/to bundles at mount with a per-formation cache, split targets into frame-invariant model space plus O(1) frame scalars, colour change-tracking, `gl.compileAsync` before the first visible frame, gate the mount on LCP rather than a 300 ms idle timeout, skip invalidate at opacity 0, and a Playwright long-task smoke wired into lhci.
